# 土豆兄弟（Brotato）1.2.0.1 本体原生公式

本档案记录游戏 1.2.0.1 本体与免费更新的计算规则。表格可按原生编号（ID）、效果键和字段查询。文中的 res:// 路径用于定位游戏内的原始定义。

`int(x)` 表示向零截断。`round(x)` 表示游戏调用的四舍五入。`ceil(x)` 表示向上取整。`clamp(x, a, b)` 把数值限制在 `a` 到 `b`。`百分比属性 / 100` 才是倍率计算用的小数。武器的冷却帧按 60 帧每秒换算，计时器参数要按所在函数辨别秒数和帧数。

## 属性来源与取值

```text
属性收益倍率 = 1 + gain_属性 / 100
永久属性 = 永久原始值 × 属性收益倍率
临时属性 = 临时原始值 × 属性收益倍率
联动属性 = 联动原始值 × 属性收益倍率
查询值 = 永久属性 + 临时属性 + 联动属性
封顶查询值 = min(查询值, 该属性当前上限)
最大生命 = int(max(1, 封顶最大生命))
玩家移动速度 = 角色场景基础速度 × (1 + 封顶速度 / 100)
```

常规闪避属性上限为 60。生命、速度、闪避、暴击查询使用各自独立的上限字段。暴击率还要与武器自带的暴击率合并，再进行命中事件中的概率判定。 `res://singletons/utils.gd` · `res://singletons/player_run_data.gd` · `res://singletons/run_data.gd` · `res://entities/units/player/player.gd`

原生属性联动以 `int(目标增量 × 实际来源量 / 来源单位)` 计算，结果进入联动属性层。来源可取材料、空武器槽、不同道具数、重复道具数、当前建筑或宠物数、活敌数量、燃烧敌人数量、活树、缺失生命百分比和某项属性。普通属性来源可设为只读永久层或读永久层加临时层。材料、敌人数等动态来源由半秒刷新入口更新。 `res://singletons/linked_stats.gd` · `res://singletons/run_data.gd`

基础 `Effect` 可以累加、按键合并、覆盖、追加唯一键或追加键值条目。特化效果可重载 `apply` 与 `unapply`。`key` 是效果或数值的主键，`custom_key` 是接收这条效果的容器键。记录里的 `value2`、`chance`、`interval` 等由对应脚本解释。 `res://items/global/effect.gd` · `res://effects/enums/storage_method.gd` · [效果与运行时消费者索引](效果实现索引.json)

## 武器基础伤害与攻击速度

武器档位的基础伤害、原生冷却、暴击、射程、吸血和缩放系数存于 `stats` 所指资源。初始化先应用武器类型加成、武器类别加成和本武器效果，再计算缩放。条件倍率、同类武器数量和额外缩放可能在进入通用公式前改变基础值或缩放列表。 `res://items/global/weapon_data.gd` · `res://singletons/weapon_service.gd` · [物品与属性目录](物品与属性目录.tsv)

```text
缩放前原始值 = 已处理类型、类别和武器专属效果的基础伤害
缩放值 = int(max(1, 缩放前原始值 + Σ(属性实际值 × 武器缩放系数)))
普通武器伤害倍率 = 1 + 伤害%/100 + 类别伤害加成 + 适用的爆炸伤害%/100
非宠物建筑的基础百分比项 = 1 + 建筑伤害%/100
建筑类宠物的基础百分比项 = 1 + (伤害% + 建筑伤害%)/100
初始化单发伤害 = max(1, round(缩放值 × 最终倍率))
```

上述类别伤害加成是匹配武器类别的百分比项转成的小数。等级缩放取当前玩家等级。命中时的敌方血量条件、敌人护甲、首领加成、暴击和特殊武器逻辑仍在后续阶段结算。 `res://singletons/weapon_service.gd`

```text
A = (攻速属性 + 武器自身及类别攻速修正) / 100
基础冷却先限制为至少 2 帧
A >= 0 时：冷却 = int(max(2, 基础冷却 / (1 + A)))
A < 0  时：冷却 = int(max(2, 基础冷却 × (1 + abs(A))))
A > 0  时：后坐及后坐时间各除以 (1 + A)
```

固定冷却上下限检查的是含攻击动作的总时长。额外换弹先从未加攻速的基础冷却乘换弹倍率，再经四舍五入和攻速换算，之后与普通冷却的比值形成实际换弹倍率。建筑和宠物的武器初始化分支不使用玩家常规攻速。建筑攻速另由建筑攻速属性与 `structures_cooldown_reduction` 关联属性之和决定。 `res://singletons/weapon_service.gd`

远程动作时长为后坐时间的两倍，显示的总间隔还要加上冷却帧除以 60。近战存在固定攻击动画时长与动作计算两条分支。动作计算分支的射程因子为 `max(0, 距离 / clamp(70 × (1 + A/3), 70, 120))`。攻击动作时间为 `(max(0.01, 0.2 − A/10) + 射程因子 × 0.15) / 动画速度`。回程基础为 `0.2/(1 + 3A)`（正攻速）或 `0.2`（其余），再除以动画速度。总动作时长取攻击动作的一半，加上回程和后坐时间。实战动作可按目标距离更新。 `res://weapons/shooting_behaviors/melee_shooting_data.gd` · `res://weapons/weapon_stats/melee_weapon_stats.gd` · `res://weapons/shooting_behaviors/ranged_shooting_data.gd` · `res://weapons/weapon_stats/ranged_weapon_stats.gd`

近战射程额外加成使用射程属性的一半，远程使用全量。初始化射程以 25 或武器的最小射程加 25 为下限。散布、弹丸数、贯穿、弹射和子弹速度各有分支。允许弹射的弹丸先结算弹射，否则消耗穿透次数。每次贯穿或弹射后更新伤害为 `max(1, 当前弹丸伤害 × (1 − 该种衰减比例))`，并写回命中盒的伤害字段。普通玩家弹丸的射程计时为 `(最大射程 + 额外距离) / 弹丸速度`，常规额外距离是 100，手动瞄准时是 50。 `res://singletons/weapon_service.gd` · `res://projectiles/player_projectile.gd` · `res://overlap/hitbox.gd`

## 命中、暴击、护甲、生命保护

玩家武器暴击概率由武器自带概率与封顶暴击属性 `/100` 合并，暴击倍率再加 `bonus_crit_damage / 100`。是否继承角色暴击对建筑有单独开关。命中盒触发时先按概率判暴击，再处理必暴击、秒杀等特殊条件。暴击单发为 `int(round(该次传入伤害 × 暴击倍率))`。以固定概率 `p` 且只计普通命中和暴击时，可从原生结算推导出每次命中期望 `(1 − p) × 普通伤害 + p × round(普通伤害 × 暴击倍率)`，后续血量条件、护甲和超额伤害仍需按实际目标结算。 `res://singletons/weapon_service.gd` · `res://entities/units/unit/unit.gd`

敌方普通受伤分支先累计适用的目标血量阈值、燃烧状态及效果行为的伤害百分比，再计算 `round(传入伤害 × (1 + 合计百分比/100))`。开启护甲时再减去敌人当前的平坦护甲，结果至少 1。敌人类还会处理首领、精英、巨型敌人及其他特殊分支。伤害统计值会按目标剩余生命封顶。 `res://entities/units/unit/unit.gd` · `res://entities/units/enemies/enemy.gd`

玩家受伤时先检查闪避，再检查可消耗的免伤次数，随后处理护甲。绕过护甲的伤害直接使用传入值。

```text
基础受伤倍率 = 15 / (15 + abs(护甲))
护甲 >= 0 时：实际受伤倍率 = 基础受伤倍率
护甲 < 0  时：实际受伤倍率 = 2 − 基础受伤倍率
应用护甲的玩家伤害 = max(1, round(传入伤害 × 实际受伤倍率))
S = max(1, 无尽系数)
受击无敌秒数 = clamp((本次受伤 / 最大生命) × (0.4/S) / 0.15, 0.2/S, 0.4/S)
```

`Player.take_damage` 还负责无敌检查、触发受击效果、最低生命限制、材料护命和角色特殊规则。 `res://entities/units/player/player.gd` · `res://singletons/run_data.gd`

## 治疗、回复与消耗品

正生命再生先截为整数 `R`。普通再生间隔为 `5 / (1 + abs(R − 1)/2.25)` 秒，基础每次回复 1 点。零或负再生不启动普通回复。低血线再生倍率在 `当前生命 < 最大生命 × 阈值/100` 时生效，所有符合条件的倍率加到 `1` 上。再生药水的原生条目为 `+3` 再生与低于半血时每跳额外 `1×` 基础回复。酷刑的计时为 1 秒，每跳按酷刑数值回复，并在正常战斗期间限制其他来源的治疗。治疗函数最终受缺失生命量、禁疗和玩家存活状态限制。 `res://singletons/run_data.gd` · `res://entities/units/player/player.gd` · `res://items/all/00_base_game/potion/potion_data.tres`

武器命中使用该武器的实际吸血概率判定。成功触发通常请求回复 1，特化效果可以改成 2。玩家收到吸血信号后只有冷却计时器处于停止状态才接受治疗，并启动计时器。原生玩家场景中的冷却为 0.1 秒。 `res://singletons/run_data.gd` · `res://entities/units/player/player.gd` · `res://entities/units/player/player.tscn`

果实治疗量为 `max(0, 果实基础回复 + 消耗品治疗修正)`。持续治疗模式将总回复 `H` 拆成 `H` 次各 1 点，定时点为 `i × 持续时间/H`，`i = 1 … H`。生命开始值、清场回满与跨波保留生命按角色和道具规则分支。 `res://effects/consumables/consumable_healing_effect.gd` · `res://entities/units/player/player.gd` · `res://main.gd`

## 燃烧、减速、击退与敌人状态

燃烧按自身的基础每跳伤害、缩放系数、触发概率和跳数初始化。原本没有燃烧的攻击使用全局燃烧的参数。已有武器燃烧时，全局燃烧的基础伤害加进该燃烧源。随后对燃烧做属性缩放和取整，再应用普通伤害或适用的建筑伤害。 `res://singletons/weapon_service.gd` · `res://effects/burning_data.gd`

```text
基础燃烧间隔 = 0.5 秒
实际燃烧间隔 = max(0.1, 基础间隔 × (1 + (总燃烧间隔增幅 − 总燃烧间隔缩减)/100))
同一燃烧槽刷新：伤害取最大值，剩余跳数取最大值
共享槽是通常的路径，开启按来源叠加的分支使用不同来源槽
每跳伤害 = max(所有独立来源槽伤害之和, 共享槽伤害)
```

每跳禁用常规闪避和护甲结算，随后消耗各槽的剩余跳数并重算总量。传播、燃烧伤害跟踪、对燃烧目标增伤及燃烧触发的减速在命中与定时器中分别处理。 `res://entities/units/unit/unit.gd` · `res://entities/units/unit/unit.tscn`

普通命中减速将对应的基础速度乘以 `speed_percent_modifier/100`，截断后加入衰减速度层。已有负变化超过基础速度的 `70%` 时拒绝进一步变化。超过 `45%` 时，新变化量除以 20。单次负变化下限是基础速度的 `−90%`。带持续时间的减速先按较长时长保持，再每秒向零恢复 300 速度单位。正衰减速度每秒向零减少 60 单位。实际移动速度至少为 0。 `res://entities/units/unit/unit.gd`

击退先算方向、大小、击退穿透及距离修正，速度向量逐步向零插值。位移使用 `击退向量 × (100 − 击退抗性 × 100)`。拉扯是负击退并使用距离相关分支。全局时间减速独立于移动减速，同一时间内保留较慢的时间因子和较长的剩余时长，时间因子下限为 `0.05`。 `res://entities/units/unit/unit.gd` · `res://singletons/entity_service.gd`

敌人生命、伤害与护甲按基础值和每波增量初始化，随后经过敌人属性修正、难度、辅助选项、合作模式、无尽系数和单位当时的强化状态。普通护甲基值按 `round((基础护甲 + 每波护甲增量 × (波次 − 1)) × (1 + 单位护甲修正/100))`。地图波次、敌人强化、弹幕和速度行为参数可沿场景追查。 `res://entities/units/unit/unit.gd` · `res://singletons/entity_service.gd` · `res://singletons/coop_service.gd` · `res://zones/zone_1_crash/zone_crash_data.tres`

## 套装、宠物与建筑

每个套装按装备中拥有该套装标签的武器计数。满足全武器计入的角色规则时，对已出现的套装使用总武器数。套装计数额外加成在此基础上加入。最终计数 `n ≥ 2` 时使用 `set_bonuses[min(n − 2, 最后索引)]`。换装后先撤掉旧的整档效果，再应用新档。武器类型或类别的专门属性改动由武器初始化分别结算。 `res://singletons/run_data.gd` · [套装参数](物品与属性目录.tsv) · `res://singletons/weapon_service.gd`

建筑道具与武器召唤使用 `scene`、`stats`、`effects` 和 `spawn_cooldown` 等资源字段。地雷生成间隔和炮塔射击冷却属于不同计时入口。建筑使用自身的基础数值、工程缩放、建筑伤害、建筑攻速、特殊射弹或爆炸分支。宠物可使用近战、远程、建筑三套初始化，另有治疗、护盾、拾取、掉落和死亡事件等独立行为。每个行为的具体参数沿相应资源中的 `ref` 或 `scene` 读取。 `res://effects/items/structure_effect.gd` · `res://effects/items/turret_effect.gd` · `res://effects/items/pet_effect.gd` · `res://singletons/weapon_service.gd`

## 材料、经验、收获与商店

基础击杀材料依次经过合作倍率、全局掉落、敌人或中立目标类别掉落修正，再应用单位行为及距离缩放。拾取时另外处理单份材料增值、拾取加倍和触发效果。消耗品掉落的普通初始概率为 `min(1, 目标基础掉率 × (1 + 所有玩家幸运之和/100))`，无尽时再除以 `1 + 无尽系数`，并处理强制掉落、道具箱和果实特例。 `res://main.gd` · `res://singletons/item_service.gd`

```text
经验增加 = 原始经验 × (1 + 经验获取%/100)
升到目标等级 L 所需经验 = (3 + L)^2 × (1 + 下一级经验需求修正%/100)
无尽波数 N = max(0, 波次 − 20)
无尽系数 = (N × (N + 1) / 2) / 100 × (2 + max(0, (波次 − 35) × 0.2))
```

波末收获与角色的活敌、活树、首领及其他结算项相加。非负结果发材料和经验，负结果扣材料。正收获的常规成长为 `ceil(当前收获 × 收获成长百分比/100)`，本体初值是 `5%`。常规波之后，无尽正收获衰减项为 `ceil(当前收获 × 20%)`。猪猪存钱罐增加的是开波时按当前材料计算的收益，本体该条目的比例是 `20%`。 `res://singletons/run_data.gd` · `res://main.gd` · `res://singletons/player_run_data.gd`

```text
w = 商店商品保存的计价波次
B = 基础价值。武器在适用时先乘 (1 + 武器价格修正%/100)
i = 0.1，通胀修正为正时改用 (1 + 通胀修正%/100) / 10
Q = 1 + (商品价格修正% + 首个匹配的特定商品价格修正%)/100
普通商品价格 = int(max(1, (B + w + B × w × i) × Q × (1 + 无尽系数(w)/5)))

刷新阶梯 = int(max(1, 0.4 × w × sqrt(1 + 无尽系数(w))))
刷新基价 = int(0.75 × w) + 刷新阶梯 × (1 + 本店付费刷新次数)
付费刷新价 = ceil(刷新基价 × max(0.1, 1 + 刷新价格修正%/100))
回收比例 = clamp(0.25 + 回收收益修正%/100, 0.01, 1)
常规回收额 = min(适用商品价, int(max(1, 回收计价 × 回收比例)))
道具箱回收额 = int(常规回收额 × (1 + 道具箱回收修正%/100))
```

价格函数另有不受折扣的分支，基础价值为 1 的回收分支直接给 1。锁定保留商品计价波次。生命商店商品按 `ceil(材料计价 / 20)` 换算。优惠券的效果是 `items_price = −5`，因此在折扣适用时参与 `Q`。免费刷新、出售和合成由商店交易分支处理。 `res://singletons/item_service.gd` · `res://ui/menus/shop/shop_item.gd` · `res://ui/menus/shop/base_shop.gd`

商店品质使用同一个随机数，从最高档向下检查。每档的波次部分为 `max(0, (w − 1 − 起始波次) × 波次增长率)`。幸运非负时乘 `1 + 幸运/100`，幸运为负时除以 `1 + abs(幸运/100)`。加上基础概率并取上限后得到该档检查阈值。商店再应用波次保证、职业限制、同武器与套装偏好、标签、排除项、持有上限和原生选池顺序。升级选项和宝箱有各自的候选池与重抽分支。 `res://singletons/item_service.gd` · [品质参数](品质参数.json)
